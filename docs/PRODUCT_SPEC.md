# 耆宿说 QISUSHUO · 产品与迭代方案

更新：2026-11-19。本文以当前可运行产品为基线。真实专家 IP 资料和 Obsidian 库尚未提供，内置人物、笔记与项目均为明确标记的虚拟示例。

## 定位与成功标准

把文化遗产团队的资料积累变成可以持续研究、复核、创作的知识工作空间。第一阶段服务个人研究者与专家内容运营者：一份资料导入后，能够找到、关联、引用、形成考证与稿件，并在重新打开后继续使用。

“有依据”只表示研究者已记录判断和出处；“示例”不因被引用、编辑或导出而变为真实史实。知识关系不是事实证明，三维模型不是测绘成果，生成文字不是专家审定结论。

## 用户旅程

| 用户 | 起点 | 主要操作 | 成果与完成条件 |
| --- | --- | --- | --- |
| 研究者 | 既有笔记和一个问题 | 导入预检 → 保留标签与双链 → 检索 → 定位历史原文 → 保存考证 | 考证包含问题、依据、支持或冲突线索、当前判断，刷新后存在 |
| 专家 IP 运营者 | 专家档案和一个选题 | 维护档案 → 关联知识 → 选主题和内容形式 → 整理提要 → 编辑引用稿 → 导出 | 稿件可继续编辑，来源版本可回溯；内置虚构人物不会被当作专家背书 |
| 项目负责人 | 一个专题目标 | 创建项目 → 关联资料和成果 → 创建任务 → 切换状态 → 检查完成度 | 待开始、进行中、已完成有一致记录；进度由任务实际计算 |
| 首次体验者 | 空间首页 | 看指南 → 浏览示例 → 三维读建筑 → 回到构件知识 → 提问 | 不需要配置模型或注册即可体验主要闭环 |

## 功能与验收

| 模块 | 本版行为 | 验收条件 |
| --- | --- | --- |
| 工作台 | 实际计数、最近资料、项目进展、考证入口 | 自有条目不显示示例标记；计数随有效记录更新 |
| 知识与来源 | 分类、时代、收藏、排序、列表/网格、编辑、归档、恢复 | 搜索空态可恢复；收藏保存；正文安全显示；历史保留 |
| 专家 | 姓名、方向、档案正文、研究观点、标签、关联 | 用户可创建真实档案；内置专家明确为虚构 |
| 导入 | Markdown/TXT/目录、frontmatter、tags、aliases、wiki 双链、相对路径 | 每批最多 500 个，单文件 2MB；原文不变跳过，更新形成版本；歧义链接报告 |
| 检索 | 中文关键词、资料范围、最近提问、带引用摘录 | 资料不足明确返回；引用点击定位指定来源版本；可转考证/稿件 |
| 三维图谱 | 旋转、缩放、搜索、分类、中心切换、选中检查区 | 节点和边来自保存的记录；关系区分知识关联与资料依据；来源端点可分别打开 |
| 建筑解读 | 原创木构概念模型、构件高亮、分层拆解、线框、复位 | 构件选择与侧栏同步；点击阅读进入真实记录；明确非文物复原 |
| 考证 | 待核实、有依据、存在争议；引用支持/冲突标记 | 结论与材料分离；历史引用可核对；不会自动升级权威状态 |
| 创作 | 科普、提纲、脚本、导览，手动编辑与 Markdown 导出 | 无模型时称资料提要；模型模式称待核对初稿；保存后仍可修改 |
| 项目 | 任务看板/列表、到期日、状态、资料成果关联 | 切换任务状态立即保存；完成度源于当前任务；刷新不丢失 |
| 数据保障 | 空间会话、版本冲突、备份、恢复、回收站 | 空间互不可见；备份包括历史；校验失败事务回滚；源码与数据库不对外开放 |

## 页面与状态设计

统一采用侧栏、顶部检索、主要工作区的稳定框架。列表页首先提供搜索和筛选；详情通过正文/来源/关联/历史切换；编辑页将正文、来源、关系放在同一个保存过程内。手机保留底部导航，详情和检查区改为单列。

| 页面 | 默认/运行状态 | 异常和边界 |
| --- | --- | --- |
| 初始化 | 打开个人空间、读取已存记录 | 存储不可用或服务失败时给出重新打开入口，不静默换存储 |
| 编辑 | 修改、预览、保存中、保存成功 | 标题必填；未保存保护；版本冲突保留输入并提示 |
| 导入 | 选文件、预检、新增/更新/跳过/失败、完成 | 文件不支持、超大、空文件、解析失败、歧义双链分别说明 |
| 问答 | 未提问、寻找依据、摘录/模型回答 | 无依据、接口失败、限流、模型失败回退摘录 |
| 图谱 | 全图、选中、筛选、旋转、缩放、关系检查 | 搜索为空、孤立节点、60 节点显示上限、设备渲染异常 |
| 建筑 | 完整、拆解、线框、部位高亮 | 渲染异常时仍保留构件说明与知识阅读 |
| 资料生命周期 | 当前版本、历史快照、归档、恢复 | 缺失来源明确提示；归档不破坏历史引用 |

三维默认按需重绘；阅读时不持续转动。支持 WebGL 的设备使用 GPU；禁用 WebGL 时使用 Three.js 官方 SVGRenderer 绘制同一套 React Three Fiber 场景，仍保留空间旋转与选择。关系列表提供低资源与键盘友好路径。渲染后端只影响画面，不影响数据。

## AI 架构与质量边界

1. 只检索当前空间内有效的知识、来源、专家记录。
2. 中文片段与标题/标签匹配召回，最多选择 6 条相关资料；本版未使用向量检索。
3. 记录每条依据的 `id + version + title + quote`，引用锁定版本。
4. 未配置模型时直接返回原文摘录；有模型时只向服务端配置的服务发送相关片段。
5. 提示区分原文、推断和资料不足，忽略资料中的指令；模型输出须带有效引用编号。
6. 超时、失败、引用越界时回退摘录，保留可完成的研究流程。
7. 人工完成来源核对和结论审阅后再对外发布；本版不实现自动发布。

来源编号有效不代表论证正确。后续模型验收要使用真实材料建立有标准答案的评测集，检查召回覆盖、出处定位、事实一致性、无资料拒答、虚构专家背书及提示注入。

## 分阶段实施路线

| 阶段 | 状态/交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 可运行研究闭环 | 本版：八个核心模块、持久化、来源版本、三维、移动端、备份 | 完整业务流程及隔离/引用/恢复回归通过 |
| P1 真实资料与模型 | 待实施：专家授权字段、资料目录规则、PDF/图片附件、OCR、语义切片、混合召回、真实模型评测 | 提供真实资料及使用范围；模型服务可用；引用准确性达到约定指标 |
| P2 团队研究与审阅 | 待实施：账号找回、组织成员、项目权限、专家审阅、发布版本、审计查看 | 身份与授权模型确认；跨账号越权测试通过 |
| P3 知识操作系统 | 待实施：Obsidian 增量同步、附件对象存储、向量索引、专题本体、内容渠道与任务编排 | 同步冲突和数据迁移可回滚；有检索基准、成本与访问量数据 |

不以增加数据库或服务数量作为架构成熟度指标。MVP 的 SQLite 与 JSON 载荷满足小空间快速迭代；大规模协作与跨对象查询成为真实需求后，再迁移至 PostgreSQL、对象存储、任务队列与 pgvector。图数据库只在复杂多跳查询价值明确时引入。

## 上手和数据迁移

在“我的产品”打开“耆宿说 · 文化知识工作台”。第一次打开即有示例。点击“使用指南”了解四步路径；从“导入资料”选择 Obsidian Markdown 文件或目录，检查报告后保存。先用“斗拱应该从哪些方面观察？”体验检索，再点引用查看原文，保存为考证或转为创作稿。

正式资料存在服务端个人空间，通过浏览器会话继续访问；不同浏览器是不同空间。本版没有账号找回，清理会话前应导出备份。单文件离线版存在浏览器 IndexedDB，与在线空间不自动同步，可以用完整备份迁移。
